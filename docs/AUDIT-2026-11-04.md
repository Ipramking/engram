## 2. Findings (verified against code; deduplicated)

### Critical
1. **Real-format API key hardcoded in the public repo and live bundle**: `eng_usr_UlZf…` fallback at old `DashboardPage.tsx:443,575` (commit 5d0c85c). Users without a loaded key copied configs pointing at that account. **Removed in this change. Revoke that key in Supabase now — it stays in git history.**
2. **New memories superseded themselves.** The conflict scan ran after the insert and included the new row, so any "moved/switched/now…" memory hid itself from recall. Personal saves could also supersede team rows (`api/_lib/conflicts.ts`, `lifecycle.ts`). **Fixed** (exclude the new id, scope personal to `team_id is null`). Rows already wrongly marked `superseded_by:` need a one-off cleanup.
3. **Any API key can manage the whole account's keys** — `/api/keys` accepts `eng_` keys, so a leaked team key can list live keys for every key and mint new ones that survive revocation (`api/keys.ts:21`). Fix: require a session token for `/api/keys`, `/api/teams`, `/api/auth/me`.
4. **`engram_snapshot` has no project authorization** — returns any project's context + latest handoff (`api/mcp.ts:668` → `_lib/continuity.ts:448`).
5. **Render team token committed**: `scripts/remote-test.mjs:3` (`3FKS…`). Rotate `ENGRAM_TEAM_TOKEN` and delete the script.
6. **Default signing secret / salt literals committed** (`api/_lib/token.ts:17`, `mcp/token.mjs:17`, `mcp/auth-db.mjs:47,220-221`). If prod ever ran on a default, `eng_live_` keys are forgeable. Rotate `ENGRAM_SIGNING_SECRET`, delete the literals, fail closed when unset.

### High
- Cross-team memory read via REST snapshot: body `teamId` overrides the authorized context (`api/continuity.ts:137-148`).
- Invited teammates never get access: invites store email without `user_id` (`db.ts:321` vs `:294`) — **teams are effectively broken**.
- Anonymous `/api/provision` tokens never expire, can't be revoked, write to the operator's MemWal account; rate limit is per-instance memory.
- `/api/chat` skips personal-scope checks, quotas, message caps; client chooses the model; no try/catch.
- `GET /api/remember?token=…` writes data (prefetchers can trigger it) and puts the master key into AI chat history and logs.
- Personal-scope snapshot/resume always fail: `teamId: "default"` written to a uuid column (`mcp.ts:571,672`).
- npx client defaults scope to `me`, so **team keys get 403** unless the model passes `scope=team` (`packages/engram-mcp/core.mjs:18`).
- One `v1.` token maps to three identities across MCP / REST / Render (`mcp.ts:231`, `auth.ts:134`, `engram-http.mjs:49`).
- **PyPI name `engram-memory` belongs to an unrelated project** — every `pip install "git+https://github.com/Ipramking/engram#subdirectory=packages/engram-py"` installs a stranger's code. Rename before advertising.
- Dashboard sessions (Supabase access token, ~1 h) never refresh; old UI then showed an empty page plus the leaked fallback key. **New UI detects 401 and asks to sign in again.**
- Live site has no CSP / X-Frame-Options / Referrer-Policy / nosniff; `ACAO: *` on HTML. GitHub: no branch protection, no LICENSE (README says MIT), no CI, private vuln reporting off.
- `pnpm audit --prod`: 1 critical, 18 high (express/proxy-addr, undici, MCP SDK OAuth leak, zod). Most fixed by `pnpm update`.

### Medium
- Recall: substring matching, category bonus beats the relevance guard, only newest 100–200 rows searched; Walrus-only hits get `createdAt=now`. Use Postgres FTS/pg_trgm + one shared scorer with `minScore`.
- Fake data: `currentEpoch: 24`, `network: 'testnet'`, `totalWalStaked` (`api/memories.ts:216-228`, `epochs.ts`), testnet Walruscan links, "SHA-256 Verified". **Removed from the UI**; strip from the API.
- `blobId` can be a MemWal job UUID or `mock-blob-0000N` (`storage.ts:217`, `memories.ts:184`).
- Duplicate Walrus writes on `rememberAndWait` timeout (`storage.ts:212`); non-atomic quota upsert; team saves use the personal 50/day limit while usage shows 150.
- No size caps on memory text / handoffs / snapshots. DELETE ignores key scope; delete-by-blobId removes every match.
- Any user can trigger the recovery worker for everyone (`POST /api/storage`); recovered personal jobs land in the shared `me` namespace.
- RLS: users can update their own `plan_tier`; `is_team_member` ignores status (backend uses service role anyway).
- `recall.ts:116` reads non-existent `content_hash`; superseded status is stored in `room`; failed metadata insert still returns `ok:true`.
- Python SDK contract drift: sends `team_code`/`limit`, reads `created_at` (server uses `teamCode`/`topK`/`createdAt`); silent offline fallback by default.
- `/mcp` answered GET with 200 JSON (spec: 405 or SSE). **Fixed.** Still echoes any `protocolVersion`, errors on notifications, accepts batches.
- `engram_tidy` in the npm client only inspects the current process; claims "semantic duplicates".
- `test:all` isn't hermetic: `phase5`/`phase6` load `.env` and mutate production Supabase.
- `api/` is never type-checked (tsconfig includes only `src`).

### Low
DB error text returned to clients; revoke reports success for unknown ids; registration reveals existing emails, no rate limit, auto-confirms; logout is a no-op server-side; 8-hex project/handoff ids; `.env.example` misses `ENGRAM_SIGNING_SECRET`/`ENGRAM_PREVIOUS_SIGNING_SECRET`; no `.gitattributes` (CRLF risk for `bin.mjs` shebang); versions scattered (npm 0.1.0, pkg 0.2.0, hosted 1.0.0, py 2.0.0); no 404 route; one 476 KB JS chunk (lazy-load routes).
